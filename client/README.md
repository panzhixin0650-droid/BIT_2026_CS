# Qt 用户端

本目录由用户端负责人独立维护，目标程序为 `user-client`。

扫一扫页面支持“充电桩报修”：输入桩编号后点击按钮，核对桩号、选择故障类型、
填写描述并确认提交。报修共用客服的“我的工单”，可刷新查看管理员回复与处理状态。
无需 AI 配置；Mock 模式可直接演示，TCP 模式需新服务端与 schema 4，见
[数据库升级说明](../database/README.md)。报修不自动停止充电，仍通过独立“充电”页结束充电。
已有草稿会保留；要换一张单，先完成当前单或点击“新建草稿”再从扫一扫进入。

## 边界

- 充电业务页面和 Controller 只依赖 `IChargingApi`；
- 开发期使用 `MockChargingApi`，联调时切到 `TcpChargingApi`；
- 用户端功能代码不实现 TCP、分帧、重连等通信细节；通信负责人后续提供
  `TcpChargingApi` 并在应用装配处替换 Mock；
- 不包含 SQL，不引用 `server/` 头文件，不计算权威金额或修改权威订单状态；
- 头像、地图和扫码属于客户端本地适配能力；只读智能助理由本地检索与独立
  `AssistantService` 适配，不经过业务 TCP、不访问账户或数据库。

推荐逐步建立：

```text
src/ui/          QWidget、Controller/ViewModel
src/api/         IChargingApi、MockChargingApi、TcpChargingApi
src/local/       头像等仅保存在客户端本机的适配能力
src/assistant/   只读知识检索、AI 本地配置与外部 Responses 适配
src/model/       页面显示模型
resources/       qrc、图标、默认头像
tests/           用户端单元测试
```

接口字段以 [`contracts/overall-interface-v1.md`](../contracts/overall-interface-v1.md) 为准，不从服务端实现反推。

## 界面实现约定

客户端界面全部使用 C++ 代码构造，不创建或引用 Qt Designer `.ui` 文件。CMake 明确关闭 `AUTOUIC`，后续页面继续遵守相同约定。

客户端使用 `src/ui/client_theme.cpp` 中的统一 QSS 作为基础视觉层：应用背景、输入框、
按钮、禁用态和底部导航由主题统一；页面内部仍可按订单状态等业务语义设置局部颜色。
视觉调整不得改变对象字段、接口调用、金额单位或订单状态语义。

当前采用「悦充 / BIT CHARGE」森林绿与暖白主题，默认窗口 480×860，最小窗口
360×640。登录页、充电页和资料页支持纵向滚动，窄窗口仍可访问输入和操作按钮。
`src/ui/charging_art.cpp` 使用 QPainter 绘制充电站、车辆及桩号输入插画，支持高 DPI，
无需下载图片、字体或增加 Qt 模块；插画不表示真实设备状态或摄像头画面。

- 首页地图配合可拖动的信息面板，定位图标进入修改当前位置；不再提供区域或空闲筛选表单。
  点击站点放大至其附近并显示预览，使用已有 API 的价格、空闲桩和预测进行单站推荐。
- 登录、站点、订单、扫码、钱包和智能助理共享主题；进行中订单使用绿色高亮，
  待支付/故障和预约状态保留各自文字与警示色。
- 钱包快捷金额支持选中反馈；手工修改金额会同步选择状态，充值仍需点击“充值”。
- 输入框与导航保留键盘操作和焦点反馈；Mock 站点 Marker 支持 Tab/Space 选择，
  预览卡的详情/导航按钮与订单卡片也保留键盘操作。

本轮视觉改动仅位于 `client/` 的页面、样式、构建清单、说明及 UI 测试中；
首页地图复用已有 `RouteMapView` 的加载机制及同一份 `map.html`，通过 Qt WebChannel
事件桥接传回站点点击，不轮询 JavaScript。API、订单 Controller、地图/智能助理服务、
TCP 协议、数据库及服务端实现保持原样。

## 运行模式与联调入口

> **默认模式：** 不填写任何运行参数时，充电业务使用 `MockChargingApi`，地图使用
> `MockMapService`。`--api` 和 `--map` 是相互独立的选项，可以只切换其中一个。

| 目的 | Command line arguments |
| --- | --- |
| 日常离线开发（默认） | 留空，或 `--api mock --map mock` |
| 仅联调 TCP，地图仍用 Mock | `--api tcp --host 127.0.0.1 --port 45678 --map mock` |
| 仅联调腾讯地图，业务仍用 Mock | `--api mock --map tencent` |
| 同时联调 TCP 和腾讯地图 | `--api tcp --host 127.0.0.1 --port 45678 --map tencent` |

日常页面开发默认保持 Mock 模式，不连接服务端或数据库：

```bash
./build/client/user-client
```

上面的命令等同于显式传入 `--api mock --map mock`。Mock 数据只存在于当前客户端
进程，适合其他成员继续独立开发和调试界面。

Qt Creator 中打开 `Projects → Run`，将 `Command line arguments` 留空即可使用
默认的业务 Mock 和地图 Mock；也可以填写 `--api mock --map mock` 明确指定。

需要进行真实 TCP 联调时，从仓库根目录先启动已经初始化好 Demo 数据库的服务端：

```bash
./build/server/server-app --database build/database/demo.db
```

再在另一个终端显式选择 TCP 模式启动用户端：

```bash
./build/client/user-client --api tcp --host 127.0.0.1 --port 45678
```

`--api tcp` 是联调测试入口；该模式只请求真实服务端，不会在接口失败时回退到
Mock。数据库初始化步骤见 [`database/README.md`](../database/README.md)，服务端
启动参数见 [`server/README.md`](../server/README.md)。

Qt Creator 中联调 TCP 时，先在终端启动上述服务端，再打开 `Projects → Run`，将
`Command line arguments` 设置为：

```text
--api tcp --host 127.0.0.1 --port 45678 --map mock
```

切回 Mock 时清空参数，或改回 `--api mock --map mock`。这些选项只改变客户端运行时
装配，不修改源码、数据库或 Git 文件。

默认请求超时为 5000 毫秒，可用 `--timeout-ms <毫秒>` 调整。连接失败、断线和
超时统一返回 `50301 SERVICE_UNAVAILABLE`；断线和 `40101 INVALID_SESSION` 会
清除客户端 token，用户需重新登录。当前服务端实际开放到哪些 TCP 消息，以
[`server/服务端网络接口.md`](../server/服务端网络接口.md) 为准；尚未开放的订单消息
会返回服务端的业务失败，不会回退到 Mock。

### 结算提示与 TCP 联调回归

TCP 适配器先解析整批回包、停止对应请求的超时计时，再在同一 Qt 线程的后续
事件中通知 Controller。这样结算提示框等待用户确认时，首页的 `station.list`
和 `order.current` 仍能正常完成；已收到的响应不会因为弹窗停留而超时。
重复响应只完成一次，断线前尚未派发的结果也不会在断线后恢复旧 token。

此前在 `readyRead` 回调内直接通知界面，结束充电后先刷新首页、再执行模态
提示框的 `exec()`，会让后续收包通知无法递归触发；超过默认 5 秒后，客户端
误判请求超时并清空 token，下一次刷新就显示登录失效。这在本机 TCP 也能
复现，并非只有远程联调才可能发生。Qt 对该行为的说明见
[readyRead](https://doc.qt.io/qt-6/qiodevice.html#readyRead) 和
[QDialog::exec](https://doc.qt.io/qt-6/qdialog.html#exec)。

本修复不改变 V1 信封、计费、订单状态或真实断线后的重新登录规则，也不自动
重发充值、停止或支付请求。新增测试使用 C++ / Qt Test：

```bash
ctest --test-dir build/client --output-on-failure \
  -R 'charging_client_tcp_(api|settlement_ui)_tests'
```

- TCP 测试覆盖提示框的嵌套事件循环、分片/粘连/重复回包、失效的延迟通知，
  以及真正超时和断线后的登录态清理；
- 界面测试使用真实 TCP socket、正式客户端与既有契约 fixture，覆盖从会话页或历史订单进入会话页结束充电的余额足够/不足情况，并检查自动结束后的状态恢复，
  再检查首页刷新、资料查询、钱包跳转和 token 均正常；不连接外部服务；
- Tailscale 手动复测时，两端保持服务运行，结束充电后在结果页面停留至少
  6 秒，然后刷新首页并进入“我的”；余额不足时继续验证充值补付。

### 地图模式与腾讯地图依赖

地图默认使用 Mock，普通客户端构建不强制 Qt WebEngine。需要构建可选的腾讯地图
适配器和内嵌路线页面时，客户端开发者需要安装完整的 Qt WebEngine 开发及运行工具：

> **额外安装项（启用真实腾讯地图前必须完成）：** 以下 WebEngine / WebChannel 包不是
> 基础 Mock 开发依赖，构建 `--map tencent` 时需要安装。

```bash
sudo apt update
sudo apt install -y \
  qt6-webengine-dev qt6-webengine-dev-tools libqt6webenginecore6-bin qt6-webchannel-dev
```

安装后使用下面的开关重新运行 CMake 配置；如果 Qt Creator 已打开，在项目的 CMake
配置中加入 `CHARGING_CLIENT_ENABLE_WEBENGINE:BOOL=ON` 并重新配置，使 Kit 能发现
`Qt6::WebEngineWidgets` 和 `Qt6::WebChannel`：

```bash
cmake -S client -B build/client -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DCHARGING_CLIENT_ENABLE_WEBENGINE=ON
cmake --build build/client
```

日常开发保持充电业务和地图均为 Mock：

```bash
./build/client/user-client --api mock --map mock
```

在已经启用 WebEngine 的构建中，需要单独联调腾讯地址解析和内嵌导航时，可以继续
使用 Mock 充电业务，只切换地图适配器：

```bash
export TENCENT_MAP_KEY='你的本地腾讯地图Key'
./build/client/user-client --api mock --map tencent
```

`TENCENT_MAP_KEY` 是腾讯位置服务控制台创建的开发 Key。Qt Creator 中打开
`Projects → Run → Run Environment` 并新增一行：变量名填写
`TENCENT_MAP_KEY`，Value 只填写 Key 本身，不要带引号，也不要重复填写
`TENCENT_MAP_KEY=`；Command line arguments 设为 `--api mock --map tencent`。
腾讯 WebService 适配器只为自身的 HTTPS 请求使用直连，避免 GNOME 空 PAC/WPAD
自动探测导致驾车、步行、公交和骑行首次规划额外等待；它不修改系统代理，也不影响
充电业务 TCP 连接。
首页控件在登录前已经创建；启动事件循环即将首页地图加入预加载，不再额外等待 80 ms。
腾讯模式不仅下载 SDK，也提前创建实际尺寸的首页画布、地图实例和固定沈阳默认视野，
让 SDK、底图和 WebEngine 在输入账号的时间内异步准备。导航页的 SDK-only 预加载等待
首页实际瓦片就绪后才开始，避免竞争首屏下载；两页共用独立的磁盘 HTTP 缓存。
缓存位于客户端 `QStandardPaths::CacheLocation/map-webengine`，最大 64 MiB，遵循服务端
缓存响应头，不强制下载/存储腾讯离线瓦片，不持久化 cookie，不进入 Git。
Qt 控件仍在 GUI 线程创建，下载、解析与就绪桥接采用
WebEngine / WebChannel 异步事件，不以循环等待或定时轮询阻塞登录输入。
预加载只使用公开的固定演示范围，不发送当前选定位置、不调用 `station.list`、用户、订单、
地址解析或路线接口。登录成功后复用同一个地图实例，才请求并更新站点与当前位置；
预加载失败不影响登录，进入首页时允许重新尝试，之后保留显式重载及中文错误。
首页和导航共用 HTML 与加载器实现，各自保留地图实例，导航的路线、缩放与跨 Tab 恢复
不受首页刷新影响。隐藏页显式设置画布尺寸，避免预加载在默认 100×220 的小视野进行。
`--map mock` 也提前准备默认地图，但不创建 WebEngine、不联网：由 QPainter 绘制内置
真实沈阳离线底图。道路、水域和绿地提前通过 OpenStreetMap Overpass API 获取并随程序
打包；几何解析与首次 QImage 绘制放在一次性后台线程中，结果通过 Qt 事件交回界面，
线程不访问 QWidget、账户或业务 API。登录后复用视口图像缓存。
Tencent 首页以同一份离线数据作为明确标注的加载预览，收到 SDK 的 `tilesloaded`
事件后切换在线底图；SDK/HTML 就绪本身不再冒充瓦片就绪。失败显示错误及重试，
不会把离线预览当成腾讯成功结果。相同视野不重复取景，首页自动取景关闭默认缓动动画。
该 Key 需要在腾讯位置服务控制台同时启用 WebService API 和 JavaScript API GL：
地址解析与步行路线由 WebService 提供，步行折线由 JavaScript API GL 在内嵌页面中
绘制。当前客户端 Demo 不保存用于服务端签名的 SK；如果 Key 强制签名校验，应改用
未开启签名校验且限制好权限/配额的开发 Key，不能把 SK 嵌入客户端。切回 Mock 时
删除本地 Key 环境变量并将参数改回
`--api mock --map mock` 或全部清空。真实模式不会在失败时偷偷返回 Mock 坐标；缺少
Key 或 Key 格式无效时程序会明确拒绝启动，地址解析失败会显示腾讯的非敏感状态码，页面加载失败也
会显示中文错误。腾讯地图 Key 禁止写入源码、仓库配置、接口 fixture 或 Git 管理的
Qt Creator 文件。

启动后输入 11 位数字手机号和 6 位演示验证码 `123456`：

- `13800000001`：登录契约中的固定演示用户，昵称为“演示用户0001”；
- 任意其他 11 位数字：在当前 Mock 进程内自动注册，昵称为“用户+手机号后4位”；
- 少于 11 位：页面直接显示格式错误，不发送 API 请求；
- 验证码为空、不足 6 位或不是 `123456`：页面显示错误，不发送登录请求；
- “发送验证码”先检查手机号，再显示固定演示码，不发送短信、不自动登录，也不自动填入；
- 新老用户走同一流程；首次通过校验后自动注册，退出后再次登录仍需输入验证码。
  登录成功会清空验证码，登录请求中手机号、验证码及两个按钮均禁用，失败后可重试。

此处验证码仅是客户端的课程演示交互，不是短信认证或服务端安全校验。Mock 与 TCP
仍复用 V1 `auth.user.login` 的 `{phone}` 请求；服务端、token 规则和数据库不变，
不要求先点击发送按钮，也不引入短信接口、验证码存储或过期机制。真实短信登录须另行
设计服务端发送、校验与防滥用机制，不能依靠客户端固定码。见
[ADR-0007](../docs/decisions/0007-client-demo-code-login.md)。

Linux 下程序会在创建 `QApplication` 前检查 Qt 输入法插件。如果桌面配置为
Fcitx/Fcitx5、当前 Qt 6 安装缺少 Fcitx 插件但提供 IBus 插件，程序只在自身进程内
回退到 Fcitx5 的 IBus 兼容接口，以便昵称输入框正常切换中文；不会修改桌面或用户的
全局输入法配置。Qt 已安装 Fcitx 插件或用户明确选择其他输入法时，程序保持原配置。

登录成功后进入用户端主界面。当前“首页”、“充电”、“扫一扫”和“我的”页面
已经可用，“客服助理”已接入只读 RAG 聊天。配置中转站与知识库维护方法见
[`assistant.md`](assistant.md)。AI、业务 API 和地图模式相互独立。

底部 5 个主入口位于带圆角和柔和阴影的悬浮框内，按相同宽度铺满可用区域，
不使用靠左堆叠或横向滚动；窗口宽度变化时由 `QTabBar` 自动重新分配每个入口的宽度。
外框与导航项之间保留内边距，窄窗口减小两侧外边距；图标在上、文字在下并居中。
仅选中项显示内嵌圆角方块，方块在宽窗口不随点击区域拉长；保留现有配色、图标和文字。
阴影由父控件直接绘制，不在背景框上安装实时 `QGraphicsEffect`，避免跨越不相邻
菜单时局部重绘擦掉中间的图标或文字。回归测试读取已显示的窗口像素，覆盖跨项悬停、
非连续区域刷新、窗口恢复、重新登录和内嵌地图切换，不以强制整窗重画的截图代替验证。

“首页”以地图为主体；搜索查询站名、区域和地址，定位图标用于修改附近搜索位置。使用方法：

- 地图使用 Expanding 策略填满首页，不在 QScrollArea 中；移除首页大插画与长站点列表。
  搜索和信息面板位于底部导航上方，推荐与附近列表可在面板内滚动。
  360×640、480×860 与横向窗口均保留底部 5 个入口，自动取景为浮层和地图署名留出空间；
- 默认使用演示坐标 `123.4200, 41.7000` 计算距离；也可以从和平区、浑南区
  快捷位置中选择，或手动输入包含城市名称的完整地址并点击“确定位置”。用户开始
  手动编辑地址后，快捷位置会自动切换到“手动输入地址”，不再保留冲突的旧选项；
- 当前 `MockMapService` 只解析演示位置及包含“和平”或“浑南”的地址，不把其他
  任意地址伪装成真实坐标。成功后统一得到经纬度并重新调用 `station.list`；
  不支持或解析失败时保留上一次有效位置，页面不会不可用；
- 未修改位置时使用默认演示坐标，位置页面提供“恢复默认位置”；
- 位置只用于当前客户端会话和本次站点请求，不写数据库，也不进入 TCP 用户资料；
- “站名或地址关键词”支持模糊查询，例如输入“和平”可以找到和平演示充电站；
- 每次 `station.list` 成功后更新多个 Marker，并自动取景至查询结果和当前位置。
  普通站点为深绿色闪电，无空闲桩为灰绿色，选中站点略大且带白边；
- 点击 Marker 只选择站点并打开预览卡，显示站名、距离、空闲/总桩数、价格、未来一小时
  拥堵预测及推荐标识。点击另一个 Marker 切换卡片，点击地图空白或“×”收起；
- 预览卡的“查看详情”继续通过 `station.detail` 显示全部电桩，“导航”复用既有地图
  Controller。没有结果时保留地图并显示小型提示；距离或预测为 null 时分别显示
  “距离待定位”“拥堵预测暂不可用”，不补造数据；
- 右侧“◎”回到当前选定位置，蓝绿色圆点与站点 Marker 区分；“＋”“−”、滚轮、
  拖动和双击控制地图。取消距离计算不会丢弃最后有效的位置，也不申请系统 GPS 权限；
- 详情页中只有 `IDLE` 桩的“预约”按钮可用；
- 站点详情中 `IDLE` 桩可直接前往“充电”确认开始；本人预约的同一电桩也可直接前往，
  不经过扫码页或预填编号表单。启动仍由服务端最终校验桩状态并复用已有预约订单；
- 预约前客户端刷新当前订单，服务端/Mock 仍会最终校验当前订单和桩状态；
- 预约成功后先弹出确认提示，用户确认后首页显示紧凑的当前预约入口。点击展开后可以
  导航、取消预约、前往充电；充电中可以打开独立会话页面。展开订单或修改位置时暂时收起
  站点预览卡，收起后恢复站点选择。页面只使用 API 返回的
  `OrderDto` 和重新获取的站点数据，不自行修改订单或桩状态；
- 预约中或充电中的当前订单提供“导航”按钮；点击后使用订单的 `stationId` 调用既有
  `station.detail` 获取站点地址和坐标，再复用统一地图导航页，不从订单字段猜测位置；
- 当前 Demo 预约没有自动过期、倒计时或违约次数，客户端不擅自增加这些状态；
- 当前 Mock 与数据库演示种子保持一致，只返回启用的浑南站和和平站。后续切换
  `TcpChargingApi` 后，由服务端聚合状态并计算距离；首页使用客户端评分选择推荐站。
- 站点预览卡和详情页均提供“导航”；起点默认使用当前选定位置且允许修改，出行方式
  提供驾车、步行、公共交通和骑行。未修改的默认起点直接复用首页已有坐标，不再解析
  “演示位置”这类展示文字；导航页临时修改的真实地址会重新解析，但不会覆盖首页的
  当前选定位置。Mock 显示静态路线摘要；使用 `--map tencent` 时，四种方式统一通过
  腾讯 WebService 获取路线数据，由客户端布局展示。Qt 管理起终点、距离用时和可折叠
  的路线详情，地图画布占用剩余空间，不再使用 360 像素硬下限。底图与线路仍由
  JavaScript API GL 在自有轻量页面中绘制，不再内嵌腾讯整套导航网页。

“充电”页面使用方法：

- 首页选桩、预约入口、扫码与手动编号统一进入本页，点击“开始充电”才提交 `order.start`。
  开始前通过 `order.current` 检查已有订单；同桩预约复用预约编号，其他活跃订单须先处理。
- 浅色背景、白色圆角卡片与柔和绿色圆环沿用全局主题，展示每次模拟会话的完成比例，功率、电量、时长及费用在下方独立显示。
  默认 180 秒充满；圆环是演示进度，不代表真实车辆电池电量。当前 Mock 设备功率为 7.2 kW。
- 客户端每秒获取当前订单，显示 API 返回的时长、电量及金额。切换页面不会停止充电。
  充满由服务端自动停止并结算，客户端关闭也不影响；服务端重启会补处理已到期的充电。
- “结束充电”需二次确认，按实际读数提前结束。结果留在充电页，余额不足可前往充值并结算。
  再次进入本页会恢复当前预约/充电/待支付订单；自动完成后的历史结果通过订单列表恢复。
- 首页只保留当前订单摘要和“查看充电”入口；完整会话操作统一在本页。

“扫一扫”页面使用方法：

- 点击底部“扫一扫”自动打开覆盖客户端内容区的相机，绿色取景角标与扫描线提示对准区域；
  底部采用与主页面一致的浅色圆角卡片，手输为主按钮，图片识别与摄像头控制并排，设备菜单保留。
  可选择“输入电桩编号”，也可导入二维码图片。成功后关闭相机并跳转“充电”待启动页。
  识别和编号确认本身不创建订单，用户必须在充电页点击开始；报修入口也位于该页。
- 二维码内容是纯文本桩编号，例如 `PILE-A-01`，支持 1–64 位英文字母、数字、下划线、点和短横线，
  首位为字母或数字。不支持商业充电网址、支付码或 JSON；服务端最终校验桩是否存在及可用。
- 图片支持 PNG/JPEG/BMP/WebP，最大 20 MB、3200 万像素；无二维码、多个不同二维码及格式不符均有提示。
  解码在独立工作线程串行执行，实时预览持续更新，最多每 250 ms 提交一帧，不堆积待识别画面。
- 识别成功、取消、离开页面或退出登录时释放摄像头；照片和视频帧只在本机内存中处理。
  无摄像头、权限不足、设备断开或占用时仍可手输或选图片；取消扫描返回首页。
- 未启用摄像头构建时提供编号输入页面。所有入口共用同一个充电控制器及现有 V1 业务接口。

点击“从相册识别”打开应用内照片网格，不再打开系统文件选择窗口。点选一张图片，

成功后进入充电待启动页，由用户确认开始订单。源码目录不存在时使用内置样例。

#### Ubuntu 真实扫码构建与验收

真实扫码是可选本地适配功能，默认 `CHARGING_CLIENT_ENABLE_SCANNER=OFF`，保持基础 Qt 构建的依赖不变。
需要摄像头和图片识别时安装 Qt Multimedia 6.2.4 与 ZBar（LGPL-2.1，动态链接）：

```bash
sudo apt install qt6-multimedia-dev libzbar-dev
cmake -S client -B build/client -DCHARGING_CLIENT_ENABLE_SCANNER=ON
cmake --build build/client
QT_SCALE_FACTOR=1 ctest --test-dir build/client -R 'charging_client_(qr_tests|tests|tcp_settlement_ui_tests)' --output-on-failure
```

腾讯地图的 `CHARGING_CLIENT_ENABLE_WEBENGINE` 和运行时 `--map` 独立配置，可与真实扫码同时启用。
识别使用 ZBar；摄像头使用 [Qt QCamera](https://doc.qt.io/qt-6/qcamera.html) 和
[QVideoSink](https://doc.qt.io/qt-6/qvideosink.html) 取帧，不需要真实充电桩硬件。

- 无摄像头：导入 [PILE-A-01.png](tests/fixtures/qr/PILE-A-01.png) 或 [PILE-B-02.png](tests/fixtures/qr/PILE-B-02.png)，
  跳转充电页核对桩号，再选择开始充电/报修。测试图片中的桩号须在当前服务端数据库中存在；
- 有摄像头：用手机显示测试二维码或打印二维码，再让笔记本/USB 摄像头扫描；
  设备菜单区分彩色/灰度通道，优先选择彩色。支持时使用 640×480 MJPEG，降低 USB 传输带宽。
  超过 5 秒未收到画面会显示连接检查提示，不能仅凭“停止摄像头”按钮判断视频已经正常传输；
  设备列表刷新时保留仍然存在的已选摄像头及视频流，只有已选设备断开才停止预览。
  接入真实摄像头后，可用 `CHARGING_TEST_CAMERA=1 ctest --test-dir build/client -R '^charging_client_qr_tests$' --output-on-failure`
  验证实际预览、设备列表刷新后的持续出图及关闭释放；该硬件测试默认跳过。
- VMware：先在宿主机把 USB 摄像头连接到 Ubuntu 虚拟机；在 Ubuntu 执行 `ls /dev/video*` 检查是否出现设备。
  虚拟机无法代替宿主机完成 USB 直通配置；笔记本集成摄像头能否直通取决于设备与虚拟机软件；
  Qt 6.2.4 在部分 PipeWire 环境中可能枚举出空设备 ID；可为客户端单独配置 GStreamer 插件目录，
  排除 `libgstpipewire.so`、保留 V4L2 等其余插件，通过 `GST_PLUGIN_SYSTEM_PATH_1_0` 指向该目录，
  并设置独立的 `GST_REGISTRY_1_0` 缓存。不要删除系统插件。若独立采集也报 JPEG 数据损坏，
  需检查宿主机占用及 VMware USB 连接，断开并重新连接摄像头后再验收；
- 手机作为摄像头需要手机提供 USB UVC 模式，或另行配置网络摄像头适配；插上普通传输数据的手机不会自动成为摄像头。
  当前扫码只使用 Qt 能枚举到的本地摄像头，不接受手机直播网址；
- 把客户端缩到 360×640 验证窄屏操作。取消或关闭扫码窗口后，旧识别结果不会写回已退出的会话。

测试使用独立工具生成的真实二维码像素，覆盖旋转、行对齐、无二维码、多个二维码、非法内容、
图片识别选桩后跳转、用户确认才开始充电，以及取消/退出清理。无物理摄像头的 CI 不能代替真实设备预览与对焦验收。

“订单”页面使用方法：

- 进入“我的 → 我的订单”时通过 `order.list` 刷新当前用户全部订单，并按创建时间倒序展示；
- 预约中、充电中和待支付订单使用高亮卡片，历史订单使用普通卡片；
- 点击订单卡片任意位置展示接口返回的时间、电量、订单价格快照和金额，卡片也
  支持键盘 Enter/Space；可空字段不由客户端自行构造；
- 详情信息使用固定标签列和内容列，字段名长度不同也不会影响右侧内容的起始位置；
- 返回“我的”或切换底部入口时自动退出详情页；再次进入先展示列表并通过 `order.list`
  刷新状态，避免继续操作已经发生变化的旧详情；
- 卡片内已经显示“点击卡片查看详情”，不再额外显示跟随鼠标的重复工具提示；
- 预约中、充电中和待支付卡片使用绿色业务高亮；鼠标悬停/键盘焦点使用中性灰绿色
  背景和边框，两者视觉含义明确区分；
- 预约中订单可在详情页取消，成功后重新调用 `order.list` 获取最终状态；
- 预约中和充电中的订单详情提供“导航到充电站”，方便赴约或充电结束后返回取车；
  已完成、已取消和待支付订单不显示该操作；
- 首页预约卡片和预约订单详情均提供“前往充电”，直接打开对应桩的待启动页面；
  充电中的订单详情提供“查看充电”，进入统一会话页面监控进度和提前结束。
- 待支付订单详情显示“立即结算”和“前往充值”。补支付请求只提交订单标识，金额、
  扣款和最终状态均来自 API；余额不足时订单保持待支付；
- 用户存在待支付订单时再次预约，客户端在当前订单检查后先弹出“请先完成结算”提示，
  用户确认后强制切换到“订单”页；服务端仍负责最终拒绝重复活跃订单；
- “前往充值”切换到“我的”。充值成功后客户端调用 `order.current` 检查待支付订单；
  若存在则自动调用 `order.pay` 重新结算。余额充足时更新服务端返回的最终余额并弹出
  “自动结算成功”，同时刷新“首页”并清除旧的余额不足提示；余额仍不足时弹窗展示
  当前余额及还需充值金额并提示继续充值，结果不确定时提示用户前往订单页核对，两种情况
  都保留待支付状态；
- 当前 Mock 为固定演示用户提供与数据库种子一致的已完成历史订单，新预约和取消
  仍只保存在本次进程中；
- 充电中的进度和结束操作放在独立“充电”页，订单页负责历史详情、
  预约取消和待支付结算。

“我的”页面使用方法：

- “我的订单”打开二级订单列表，顶部“返回我的”回到个人资料与钱包。

- 进入页面时自动通过 API 刷新手机号、昵称和余额；
- 输入 1 到 32 个字符的昵称并点击“保存”，成功响应后使用返回的 `UserDto`
  同步“我的”资料和“首页”欢迎语，不使用输入框内容提前修改其他页面；
- 可选择 10、20、50、100 元，或手动输入 0.01 到 10000 元充值；
- 页面余额只使用充值响应中的 `balanceCents`，不在 UI 中直接累加；
- 没有待支付订单时，充值到账后弹窗展示服务端返回的当前余额；
- 在“我的”点击个人资料卡进入详细信息，点击头像进入完整预览，再点击“从相册更换头像”；
  相册提供“小芽、小猫、小熊、小兔”四款基础头像，点击即应用并返回完整预览。
  相册图片可先预览，再点击“设为头像”保存；返回不改变原头像。无效图片显示提示；
- 四款头像由 QPainter 绘制，沿用森林绿与暖白主题，无需联网或额外图片插件；两种来源均归一化到
  最大 512×512、保存为 PNG，按用户隔离，重新登录或重启后恢复；
- 点击“退出登录”会清除 Mock token 并返回登录页。

头像不经过 TCP。Linux 下使用 `QStandardPaths::AppDataLocation` 保存图片，并由 `QSettings` 保存每个用户对应的相对路径；这些运行时文件位于仓库外，不会进入 Git。

## 页面异常恢复

- 返回登录页（退出或接口返回 `40101`）时，统一清空页面 Controller 的待处理请求与
  账户展示；上次会话的延迟响应不更新新会话页面，也不会继续触发扫码启动等后续操作。
- 订单进度响应只更新正在查看的同一订单详情；返回列表、切换底部入口或查看其他订单后，
  旧响应不会重新打开原详情。离开订单入口也会放弃尚未完成的导航跳转意图。
- 预约前置检查期间阻止重复预约，订单导航等待期间阻止并发提交订单操作。
- API 返回 `50301` 后恢复对应操作控件并显示中文提示。超时并不证明业务操作未执行，
  应在恢复连接后刷新资料/订单核对；页面不会自动重发充值、支付或启动充电等写操作。
- 异常回归使用测试内的延迟 `IChargingApi` 替身，覆盖会话失效、退出后旧响应、超时恢复、
  重复提交与离开页面后的进度/导航响应；不修改 TCP 适配器或 V1 契约。

可单独运行：`ctest --test-dir build/client -R charging_client_ui_recovery_tests --output-on-failure`。

## 公共交通导航

进入站点导航（或预约中/充电中订单的导航），在出行方式选择“公共交通”，确认起点后
点击“开始导航”。需要导航到站点以外的目的地时，本版仍仅支持当前选定站点作为终点。

- 默认 `--map mock`：显示公共交通起终点和离线 Mock 提示，不提供真实线路/班次。
- `--map tencent`：沿用上面的 WebEngine 构建和 `TENCENT_MAP_KEY` 配置，直接调用
  `/ws/direction/v1/transit/`。显示默认推荐方案，地图分别绘制步行段和交通线路；
  原生“详情”面板显示线路名、上下车站和服务返回的运营警告。
- “客户端导航”仍需要互联网访问腾讯。它不新增充电项目服务端接口；从订单进入时，
  获取站点坐标仍使用原有 `station.detail`。路线方式不会上传为订单字段，也不改变计费。
- 没有路线或分段数据无效时提示失败；API 数据与地图 SDK 分别处理错误，不用网页加载
  成功冒充路线可用。路线说明是纯文本，不执行远端 HTML。本版不保证实时班次、不购票。
- 腾讯公交返回状态码 `348` 表示当前起终点没有可用公交方案，客户端提示更换起点或
  出行方式，不将它误报为 Key 权限问题；近距离站点可改用步行或驾车。

手工验收：启动 `--api mock --map tencent`，以已知有公交/地铁连接的沈阳市地址为起点，
选站点并生成公共交通路线，确认页内出现公交换乘方案或明确的无路线提示；再切换驾车、步行
确认仍正常。Mock 下四个选项都应显示各自的离线摘要。决策见
[ADR-0003](../docs/decisions/0003-client-transit-navigation.md)。

## 骑行导航

在同一导航页选择“骑行”，确认起点并点击“开始导航”。本版骑行指普通自行车，
不提供电动自行车/摩托车专用路线或共享单车车辆查询。

- `--map mock`：只显示骑行起终点和离线 Mock 提示。
- `--map tencent`：客户端直接调用腾讯骑行路线接口，复用步行地图绘制方式，展示路线、
  距离和预估用时。沿用 `TENCENT_MAP_KEY`、WebService 与 JavaScript API GL 权限，
  构建仍需启用 WebEngine；服务权限或配额不足时显示失败，不回退 Mock。
- 无路线、返回数据无效、超时或网络失败时显示骑行错误提示，允许修正起点后重新查询。
  该能力不增加项目 TCP 消息，不影响订单或数据库。

手工验收：使用 `--api mock --map tencent`，选择已知可骑行到达站点的起点，切换“骑行”
并生成路线，检查地图折线、距离与用时；再切回“步行”确认方式显示正确。自动测试使用
内存中的腾讯响应替身，覆盖骑行成功、无路线、错误数据和超时，不访问公网。
参见 [ADR-0004](../docs/decisions/0004-client-cycling-navigation.md)。

## 自有地图交互与验收

首页实现分为 `station_browser_home.cpp`（布局与浮层）、`station_map_view.*`（地图与
Marker）、`demo_map_backdrop.*`（默认离线底图与缓存）及 `station_preview_card.*`（站点信息）。
Mock 默认底图由真实 OpenStreetMap 道路、立交、铁路、水域多边形、绿地和地名绘制，
替换人工网格与虚构河道。保持浅绿、暖白与森林绿主题，数据日期、来源、请求范围与
原始响应 SHA-256 记录在 `resources/map/shenyang.json`；运行时无需 Key 或网络。
首次解析/绘制在后台完成，视野外要素裁剪，相同尺寸、中心、缩放与 DPI 复用缓存。
Marker 和当前位置仍使用接口经纬度；只对离线源数据做 WGS84 到近似 GCJ-02 的显示对齐，
不修改业务坐标，不把离线道路用于路线规划或实时交通。超出内置沈阳范围显示提示。
地图保留可点击的 © OpenStreetMap 署名；数据以 ODbL 1.0 分发，约 4 米显示简化不用于
测绘精度保证。更新方法与许可见 [离线地图来源说明](resources/map/NOTICE.md)。Tencent 模式使用
共享 `RouteMapView` / `map.html` 的站点场景，Qt WebChannel 只暴露就绪与站点点击事件；
ID 使用字符串传递以保留 qint64 精度。桥接方式参考
[Qt WebChannel JavaScript API](https://doc.qt.io/qt-6/qtwebchannel-javascript.html)。
腾讯加载期间保留明确标注的 OSM 离线预览；瓦片就绪后移除，失败时保留错误及重载按钮，
不更换 IMapService、不返回成功 Mock 路线；导航页面继续使用原有路线场景。

以下操作针对路线导航页：

- 点击“＋”“−”放大、缩小地图，也可滚动鼠标滚轮、双击放大或拖动平移。
  “显示全程”重新适配整条路线；缩放不改变输入框、按钮、网页或文字大小。
- 起终点在地图上分别标“起”“终”；公交步行段使用不同颜色，分段之间不补造直线。
- 同一个 SDK 配置初始化一次地图，重新规划只更新线路。服务请求与地图初始化期间，
  “开始导航”均禁用；SDK 加载或初始化超过 15 秒后恢复操作并给出错误。
- 切换到充电、客服助理等底部主入口时，保留当前路线、地图实例和缩放状态；切回“首页”
  后仍停留在原导航页并恢复同一画布。只有点击导航返回、换站点或退出登录时，才取消
  在途路线/临时起点解析并清理路线，旧结果不会覆盖新站点。
- 地图加载失败会区分脚本地址、内置页面、SDK 下载/接口、地图初始化、路线绘制、渲染
  进程和超时。可恢复错误显示“重新加载”，直接复用已取得的路线数据重建地图，不重复
  请求路线服务；地图不可用时仍可查看路线摘要和文字详情。
- 最小 360×640、默认 480×860 及横向窗口都检查地图和展开详情不越过底部导航。
  详情面板可以滚动和收起，地图区域随着窗口和详情的高度变化适配。
- 这是路线规划和交互查看，不包含持续 GPS、语音导航或偏航自动重算。
  底图仍需联网；复用地图不会消除 WebEngine 首次启动、SDK/瓦片下载或显卡性能的影响。

离线检查（默认 Mock 构建）：

```bash
ctest --test-dir build/client -R 'charging_client_(station_map|map|navigation)_tests' --output-on-failure
```

启用 WebEngine 后，导航测试使用当前桌面显示平台；无桌面的 CI 可用
`xvfb-run -a ctest --test-dir build/client --output-on-failure`。
不要强制该测试使用 Qt 6.2 的 `offscreen` 软件渲染：重载地图时可能在 Qt Quick 场景图内崩溃。

VMware 下可对使用 SDK 替身的 Xvfb 测试设置 `LIBGL_ALWAYS_SOFTWARE=1`，但不要把这个
测试参数默认带入真实腾讯地图客户端。本机 Qt WebEngine 会屏蔽该软件渲染器的 WebGL，
日志出现 `WebGL1/2 blocklisted`，页面提示地图绘制失败。遇到该情况先移除这个变量，
以正常桌面图形配置启动，再验证真实底图与站点标记；替身测试通过不能证明 WebGL 可用。

导航测试会用本机 HTTP SDK 替身执行自有 HTML，检查缩放上下限、
显示全程、地图实例复用、跨入口恢复、分类错误、显式重载和尺寸变化。测试不读取真实
Key，不访问腾讯；同时覆盖站点 Marker/位置、点击桥接与冒泡、选中状态、筛选后更新、
画布恢复及失败重载。首页测试还覆盖窄屏布局、查询空结果、拖动/缩放/重新定位和 null 预测。
预加载回归另外检查：登录输入保持焦点，登录前没有用户/订单/站点请求，首页在隐藏状态
已准备好有效尺寸与默认范围；模拟 3.2 秒账号输入后，登录切换复用同一 WebEngine 实例，
不重新加载 HTML/SDK；另外模拟瓦片延迟 2 秒及瓦片未就绪，检查登录期加载、真实瓦片事件、
预览切换、HTTP 缓存配置和重复取景。背景失败可恢复。Mock 检查预热、输入响应、真实数据、
底图缓存、实际 paint 与 Marker。
测试输出预热及登录切换耗时，以本机离线回归的 500 ms 为目标，不把测试替身的速度当成
真实腾讯服务承诺：真实底图瓦片仍取决于网络、Key 权限、显卡和机器性能，SDK/地图实例
就绪不代表所有瓦片完成下载。本环境缺少有效 Key 时不能验证腾讯在线首帧的时间。
后台页面的可见性与生命周期按 [Qt WebEngine 页面说明](https://doc.qt.io/qt-6/qwebenginepage.html#visible-prop)
管理，登录前不切换页面、不弹出额外窗口，也不转移输入焦点。
可用 `BIT_CLIENT_SCREENSHOT_DIR` 指定目录运行 `charging_client_station_map_tests`，导出
默认、窄屏和横向窗口的首页/站点卡截图；截图是测试产物，不提交到仓库。
真实 SDK 的鼠标/触摸板手感、权限/配额、地图瓦片及实际路线必须用本地有效 Key 验收：
按四种方式分别规划，缩放与拖动，展开详情、缩小窗口，再返回重进；断网后确认有错误
而非永久禁用或成功 Mock。Key 需要对应 WebService 和 JavaScript API GL 的使用权限。

实现决策见 [ADR-0006](../docs/decisions/0006-client-api-map-navigation.md) 和
[ADR-0011](../docs/decisions/0011-client-offline-basemap.md)。

首页交互：地图下方的手柄可拖动或点击，在收起、默认、展开之间切换。收起只保留搜索框；
点击搜索框进入独立搜索页，最近 8 次搜索按登录账号保存。首页依次显示上次使用一站、推荐一站、附近最多四站。
选站后可选桩预约或进入充电页。“全景”展示搜索结果中的站点，
“附近”回到选定位置；Ubuntu 使用演示或手动解析的位置，不是手机 GPS。
详细状态与数据规则见 [ADR 0013](../docs/decisions/0013-client-map-discovery.md)。

地图交互：拖动或缩放时面板收起为搜索框；点击空白处隐藏面板，再次点击恢复。
右上角提供加减缩放、全景、附近。点击地图电站标记或推荐/附近/搜索结果中的电站，
都会定位并放大到该站附近，同时展开站点信息。详情异步返回不会撤销用户刚才的收起操作。
选站卡集中展示名称、地址、距离、空闲桩和价格，提供“导航到站”“选桩充电”；无空闲桩
或停用时改为“查看电桩”。地图工具与卡片操作保留至少 44×44 逻辑像素的点击区域。
定位图标进入位置设置；“确定位置”立即更新附近距离与路线起点。

统一顶栏使用“悦充”品牌，显示刷新和登录账号。我的资料卡进入详细信息，昵称显式保存；
点击头像进入完整预览，再从测试相册更换。故障报修、我的工单从“我的”独立进入，
客服助理里的真人客服入口仅保留模拟客服对话。地图全屏同时隐藏底栏，继续拖动/缩放不会
退出全屏，点击空白或选站恢复。见 [ADR 0014](../docs/decisions/0014-client-shell-profile-support.md)。

推荐和附近只纳入正常运营、有空闲桩、距离有效的电站。附近优先 10 公里，不足四站可补充
至 30 公里；推荐按距离 55%、空闲情况 25%、价格 15%、拥堵预测 5% 综合评分，先在
10 公里内选一站，没有可用候选再扩大到 30 公里。缺少预测不会淘汰候选；没有可用站点
时明确显示空状态。规则、公式和研究依据见 [ADR 0015](../docs/decisions/0015-client-location-recommendation.md)。
