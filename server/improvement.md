# 服务端改进项记录

本文档用于记录服务端和同进程管理员端后续需要讨论、确认和实现的问题。

## 使用流程

1. 讨论阶段：只分析问题、影响范围、可选方案和实现风险，不修改服务端代码。
2. 记录阶段：当负责人明确说“记录这个修改项”时，将已经确认的内容追加到本文档。
3. 实现阶段：只有负责人明确说“根据 improvement.md 开始修改”后，才统一处理本文档中的待实现项。
4. 验证阶段：实现后补充测试结果、相关提交或 PR，并将已完成项标记为 `DONE`。
5. 版本阶段：正式完成的改动同步追加到 [`版本日志.md`](版本日志.md)；如果涉及客户端联调的接口，再同步更新 [`服务端网络接口.md`](服务端网络接口.md)。

## IMP-004：新增充电站时联动生成可编辑电桩明细

- 状态：DONE
- 记录日期：2026-09-04
- 提出背景：当前新增充电站只填写“初始电桩数”，服务端随后按数量自动生成编号、类型和功率。自动生成的电桩明细在创建前不可编辑，管理员无法在站点创建过程中录入真实设备信息，导致编号、充电类型和额定功率可能与实际部署不一致。
- 目标结果：在新增充电站页面中，电桩数量与电桩明细联动。管理员修改数量后，表单下方立即展示对应数量的电桩明细行，并可在提交前编辑每个电桩的编号、类型和额定功率；站点及其初始电桩作为一个完整业务对象保存。
- 影响范围：服务端管理员 UI 新增站点表单、管理员端进程内 `AdminFacade`/`ApplicationService`、SQLite Repository 与内存 Repository 的站点批量创建事务、相关测试和服务端接口文档；不涉及客户端 TCP 网络协议。
- 接口/数据影响：将管理员端创建站点入参从 `pileCount` 调整为可携带 `piles` 明细数组（为兼容过渡期可保留数量字段但以明细数组为准）；每项至少包含 `pileCode`、`pileType`（`FAST`/`SLOW`）和 `ratedPowerKw`。服务端继续生成 `stationId`、桩 ID、创建时间及初始状态 `IDLE`；不新增数据库表或字段，沿用现有 `charging_stations` 与 `charging_piles` 结构。
- 验收标准：
  - 新增站点页面的电桩数量范围为 0–100；数量为 0 时不展示明细并创建空站点。
  - 数量增加时追加默认明细行，数量减少时移除末尾未保存行；已有行的编辑内容尽量保留。
  - 每行可编辑电桩编号、类型和额定功率；类型切换可以提供默认功率建议，但不能覆盖管理员已经手动修改的功率。
  - 提交前校验所有必填字段、功率范围、编号格式及明细内编号唯一性；服务端再次校验与数据库已有编号的唯一性及站点状态约束。
  - 站点和全部初始电桩在同一事务中提交；任一明细非法或写入失败时整体回滚，不留下半成品站点或电桩。
  - 创建成功后返回真实站点 ID 和完整电桩明细，管理列表立即可见并自动展开所属电桩；站点电桩数量、可用数量和在线率从实际关联数据聚合。
  - 单独新增电桩的既有流程继续可用；新建电桩状态固定为 `IDLE`，状态操作仍在设备管理场景中完成。
  - 更新服务端测试、`server/服务端网络接口.md`（如涉及管理员端契约）及必要的总体契约说明；客户端 TCP 接口和数据库迁移保持不变。
- 讨论结论：不再仅依赖服务端自动交替生成快慢充和固定功率作为最终数据；默认值只用于帮助快速填表，管理员可以在提交前逐桩修改。站点创建和初始电桩创建保持原子性；数量为 0 明确表示创建空站点，之后再从电桩管理新增。本项已按该方案实现。
- 依赖与风险：需要同步修改 SQLite 与内存两套 Repository 的批量创建接口和回滚测试；需要确定桩编号格式校验规则及功率上下限；若保留旧 `pileCount` 调用方，需明确兼容策略，避免新旧入参产生歧义。

## IMP-005：区分充电站与展开电桩的列表层级

- 状态：DONE
- 记录日期：2026-09-04
- 提出背景：当前充电站列表使用同一个 `QTreeWidget` 展示站点和展开后的电桩。父子行虽然存在缩进，但字体、行高、背景和信息组织基本相同，电桩行还把类型、功率和累计数据拼接成描述文字，导致主实体与从属设备混在一起，表格层次不清。
- 目标结果：保留站点展开查看所属电桩的交互入口，同时通过字号、字重、行高、背景、缩进和列内容建立清晰的主从层级。展开区域只承担查看设备基本信息和进入设备管理页的职责，不在站点页面重复承载完整设备详情与操作。
- 影响范围：服务端同进程管理员 UI 的充电站 `QTreeWidget` 展示、站点与电桩行样式、列内容及行级操作布局；不修改数据库、Repository、ApplicationService 或客户端 TCP 接口。
- 接口/数据影响：无。继续使用现有站点和电桩 DTO；不新增字段、表、消息或状态。
- 验收标准：
  - 站点父行使用较大的常规/半粗字体（约 14–15px）、较高行高（约 44–48px）和清晰的名称、地址、状态层级。
  - 电桩子行使用较小的常规字体（约 12–13px）、较紧凑行高（约 34–38px）、浅色背景和明确左侧缩进；不能与站点行视觉等同。
  - 展开区域的电桩只展示四项基本信息：电桩编号、类型、额定功率和状态；不再显示电桩 ID、累计充电次数、累计充电时长等扩展数据。
  - 四项信息按清晰的子表格列展示，不再将多项数据拼接成“电桩 · xxx”“额定功率 xxx kW”等长描述。
  - 站点专属的区域、地址、电价等列在电桩子行中留空，不重复复制站点字段；站点列仍保留可用/总数、在线率、状态和操作等主数据。
  - 站点行保留“详情”和“更多”；展开区域的电桩移除“详情”按钮及开机、关机、重启、标记故障、删除等设备操作，完整管理功能统一放在充电桩管理页面。
  - 调整后仍可展开/收起站点、打开站点详情，并保留刷新后的展开状态；不同窗口尺寸下不出现明显重叠或无意义横向滚动。
  - 状态文字、颜色语义和按钮名称继续遵循 [`uidesign.md`](uidesign.md) 与 [`logic.md`](logic.md)，不增加开发阶段说明性小字。
- 讨论结论：优先在现有 `QTreeWidget` 上通过父子行样式和四列基本信息完成层级优化，不立即引入复杂的嵌套表格。站点页面只提供设备摘要，设备详情与操作不在此重复；本条以 2026-09-04 本次修订为准，覆盖此前关于在子行展示累计数据、详情按钮和设备操作的旧方案。本项已按该方案实现。
- 依赖与风险：需要在实际窗口尺寸下检查列宽和子行缩进的平衡；现有树表父子行共用表头，需要通过留空和字段映射保证四项设备信息容易理解。如仍不清晰，可评估站点主表加展开区域内轻量子表，但应保持原有展开语义。

## IMP-006：从充电站行快速新增所属电桩

- 状态：DONE
- 记录日期：2026-09-04
- 提出背景：当前只能从“充电桩管理”页面打开新增电桩窗口，再手动选择所属站点。管理员已经位于某个充电站的操作菜单时，缺少针对该站点直接新增设备的快捷入口。
- 目标结果：在每个充电站行的“更多”菜单中增加“新增充电桩”，打开表单时自动关联当前站点，让管理员直接填写并创建该站点下的电桩。
- 影响范围：服务端同进程管理员 UI 的充电站操作菜单、新增电桩对话框复用和创建成功后的列表刷新；沿用现有 `AdminFacade`、`ApplicationService` 与 Repository 创建电桩能力。

  - 启用站点的“更多”菜单包含“新增充电桩”；停用站点的该菜单项不可用。

  - “充电桩管理”页面原有的通用新增入口继续保留，两种入口复用同一套表单和校验逻辑，避免行为不一致。
- 讨论结论：站点行入口服务于“给当前站点加桩”的上下文操作，通用入口服务于先选站点再新增；两者都调用现有服务端创建能力，不新增另一套业务接口。本项已按该方案实现。

## IMP-008：双击展开电桩跳转并定位到充电桩管理页

- 状态：DONE
- 记录日期：2026-09-04
- 提出背景：充电站展开区域只应提供所属电桩的基本信息，但管理员仍需要从当前站点快速进入某台设备的完整管理位置。若仅移除详情和操作而没有明确入口，管理员还需手动切换页面并重新查找电桩。
- 目标结果：管理员双击充电站下展开的电桩行后，系统跳转到“充电桩管理”页面，自动显示、选中并滚动定位到刚才双击的电桩，便于继续查看详情或执行设备操作。
- 影响范围：服务端同进程管理员 UI 的树表双击事件、侧栏页面导航、充电桩搜索/筛选状态、列表选中与滚动定位；不修改服务端业务接口、Repository、数据库或客户端 TCP 协议。
- 接口/数据影响：无。使用电桩行已有的 `pileId` 和 `stationId` 完成页面内导航与定位。
- 验收标准：
  - 双击站点父行仍按原有逻辑处理，不误触发电桩跳转；只有双击电桩子行才跳转。
  - 跳转后侧栏和页面标题正确切换到“充电桩管理”。
  - 系统自动清除会隐藏目标电桩的关键词和状态筛选，并将所属站点筛选设置为目标电桩的站点，确保目标行可见。
  - 列表刷新后按稳定的 `pileId` 查找目标，而不是依赖刷新前的行号；自动选中目标行并滚动到可视区域。
  - 定位成功后只高亮目标行，不自动打开详情、不自动执行任何设备操作。
  - 若目标电桩在跳转前已被删除或读取失败，仍进入充电桩管理页并显示明确提示，不选中错误行。
  - 完成跳转后，管理员可在充电桩管理页使用既有详情、开关机、重启、标记故障和删除功能。
- 讨论结论：站点展开区是设备摘要入口，双击是进入完整设备管理的快捷方式；不在摘要区保留“详情”按钮或设备操作。本项已与修订后的 `IMP-005` 配套实现，并以本次记录覆盖此前对子行操作入口的旧设想。
- 依赖与风险：刷新列表时筛选控件会触发多个信号，需要避免重复刷新导致定位丢失；系统字体与鼠标操作之外，还应考虑后续为键盘用户提供等价入口，但不在本项强制增加新按钮。
