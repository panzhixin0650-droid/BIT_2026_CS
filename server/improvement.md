# 服务端改进项记录

本文档用于记录服务端和同进程管理员端后续需要讨论、确认和实现的问题。

## 使用流程

1. 讨论阶段：只分析问题、影响范围、可选方案和实现风险，不修改服务端代码。
2. 记录阶段：当负责人明确说“记录这个修改项”时，将已经确认的内容追加到本文档。
3. 实现阶段：只有负责人明确说“根据 improvement.md 开始修改”后，才统一处理本文档中的待实现项。
4. 验证阶段：实现后补充测试结果、相关提交或 PR，并将已完成项标记为 `DONE`。
5. 版本阶段：正式完成的改动同步追加到 [`版本日志.md`](版本日志.md)；如果涉及客户端联调的接口，再同步更新 [`服务端网络接口.md`](服务端网络接口.md)。

## 状态说明

| 状态 | 含义 |
| --- | --- |
| `DISCUSSING` | 正在讨论，尚未确认记录 |
| `TODO` | 已确认，等待统一实现 |
| `BLOCKED` | 受到外部条件阻塞，需要补充信息或其他模块配合 |
| `DONE` | 已实现并完成验证 |
| `WONT_DO` | 讨论后决定暂不实现 |

## IMP-001：精简管理员登录界面文案和提示区域

- 状态：DONE
- 记录日期：2026-09-03
- 提出背景：管理员服务端窗口当前显示运行模式、业务功能介绍、登录说明和课程 Demo 账号等辅助文案。这是服务端固定运行界面，不需要向管理员展示数据源、课程演示信息或宣传性说明，现有小字较多且容易造成界面干扰。
- 目标结果：精简管理员登录界面和管理后台中的非必要提示，只保留必要的品牌标题、账号输入框、密码输入框、登录按钮以及实际业务内容和必要的服务状态。

- 接口/数据影响：无；不修改 SQLite Repository、数据库文件、TCP 接口、命令行参数或后端运行逻辑。
- 验收标准：管理员登录页和登录后的管理后台均不再出现“当前模式”“SQLite 本地数据库”“内存开发模式”“站点运营 · 设备监控 · 用户管理 · 营收分析”“登录后台，查看充电业务运行情况”“课程 Demo 账号：admin / 123456”及对应提示区域；服务端仍能正常使用 SQLite 数据库启动和读写数据。
- 讨论结论：管理员窗口只有一种对外呈现方式，不提供运行模式展示或切换入口；登录界面不展示课程 Demo 账号，不展示宣传性功能列表或登录说明；本项只删除 UI 中的非必要文案和提示区域，不删除后端保留的测试替身能力。

## IMP-002：优化管理员登录界面的文字层级与布局

- 状态：DONE
- 记录日期：2026-09-03
- 提出背景：当前管理员登录界面的标题、字段标签、输入区域和登录按钮在字号、间距、对齐方式及垂直位置上还需要进一步优化，整体视觉重心不够统一。
- 目标结果：建立清晰、舒适、专业的登录表单层级，让管理员打开页面后能快速识别标题、输入账号密码并完成登录；文字大小、间距和位置与 [`uidesign.md`](uidesign.md) 中的层级和简洁原则一致。
- 影响范围：服务端同进程管理员 UI 的登录页面布局和文字样式。
- 接口/数据影响：无；不修改登录接口、认证逻辑、SQLite Repository、数据库、命令行参数或后端运行逻辑。
- 验收标准：品牌标题、页面标题、字段标签、输入内容、错误反馈和登录按钮具有明确且不过度的字号层级；表单整体在登录卡片中视觉居中，账号、密码、错误提示和登录按钮保持自然垂直间距与一致对齐；窗口缩放后布局仍然稳定可用；不通过增加说明性小字填充空白或解释操作。
- 讨论结论：登录页优先保证信息层级、可读性和操作效率，不追求堆叠装饰或文字内容；具体字号、间距和布局方案在统一实现时根据现有界面和实际运行效果调整。

## IMP-003：数据概览自定义日期范围与文案清理

- 状态：DONE
- 记录日期：2026-09-03
- 提出背景：数据概览营收折线图目前仅支持“近 7 日”和“近 30 日”，管理员无法查看任意业务日期范围；同时页面存在面向开发阶段的说明性小字和技术状态标识，不符合运营管理界面的简洁规范。
- 目标结果：为营收折线图增加自定义起止日期查询，并清理数据概览页中不必要的说明文案和开发实现信息，使页面聚焦于运营数据和管理操作。
- 影响范围：服务端同进程管理员 UI、数据概览查询参数及营收趋势聚合逻辑；不涉及客户端 TCP 接口。
- 接口/数据影响：管理员端内部 `ApplicationService::getDashboard`/`AdminFacade` 查询语义需要支持日期范围；继续读取现有订单支付时间和金额，不新增数据库表或字段，不改变客户端网络协议。
- 验收标准：
  - 右上角范围选择保留“近 7 日”“近 30 日”，并增加“自定义”；选择自定义后显示起始日期、终止日期和确认查询操作。
  - 起止日期按中国时区解释，起始日和终止日均包含；起始日期不得晚于终止日期，查询跨度限制为不超过 366 天；非法输入显示清晰的业务提示。
  - 自定义日期只影响营收折线图；“今日营收”“本月营收”“累计营收”三个指标卡保持各自固定业务含义。
  - 日期范围内没有订单的日期仍显示为 0，折线日期连续；图表标题“营收趋势（元）”和状态标题“电桩状态”等必要业务文案保留。
  - 删除“运营核心指标”和“状态由服务端数据源实时聚合。”等说明性小字。
  - 删除页面顶部的 TCP 地址/启动状态、SQLite/内存模式标识，以及侧边栏“SERVER ADMIN”等开发阶段技术信息；不在运营 UI 中暴露 TCP、SQLite、Repository、内存模式等实现概念。
- 讨论结论：自定义范围仅作用于营收趋势图，默认使用中国时区并包含边界日期；指标卡不随图表范围改变；技术运行状态和实现说明移出面向运营人员的界面；本项先记录，待负责人明确授权后统一实现。
- 依赖与风险：无数据库结构依赖；需要同步更新仪表盘相关单元测试，确保既有 7/30 日行为和自定义日期校验均通过。

## 修改项模板

后续每个修改项使用以下格式追加，编号保持递增，不删除历史记录：

```markdown

- 状态：TODO
- 记录日期：YYYY-MM-DD
- 提出背景：说明当前问题或使用场景。
- 目标结果：说明完成后应该达到什么效果。
- 影响范围：服务端模块、数据库、客户端接口或管理员端 UI。
- 接口/数据影响：新增或调整的消息、字段、表、状态和兼容性要求；无则写“无”。

- 讨论结论：记录已经确认的方案和明确不做的内容。
- 依赖与风险：记录数据库负责人、客户端负责人或其他外部依赖；无则写“无”。

- 完成实现：YYYY-MM-DD

```

## 记录原则

- 讨论中的想法不自动视为开发授权，也不自动写入“已确认”列表；
- 只记录已经明确的目标和约束，不把推测写成需求；
- 涉及跨模块接口、DTO、错误码或数据库结构时，先记录影响，再决定是否需要同步其他模块文档；
- 不在本文件中粘贴密码、token、数据库密钥或其他敏感信息；
- 已完成项保留在本文档中，便于追踪历史，不直接删除。
