# ADR-0004：用户端自行车骑行导航

- 状态：Accepted（本任务已实现，合并后进入主线）
- 日期：2026-09-05
- 授权：用户在公共交通导航增量之后明确要求增加骑行。

## 决策与消费者

客户端导航页增加本地 `RouteMode::Cycling`（契约记为 `CYCLING`），供前往充电站的
自行车路线查询。保留已有驾车、步行和公共交通语义。

腾讯官方 [路线规划文档](https://lbs.qq.com/webservice_v1/guide-road.html) 提供
`/ws/direction/v1/bicycling/` 自行车路线接口。客户端复用步行的 HTTPS 请求、压缩折线
解码和 JavaScript 地图绘制，按响应显示距离（米）和预估用时（分钟）；与步行分别使用
`bicycling/walking` 路径和中文方式标签。真实模式不使用未经验证的 Web URI 骑行参数。

当前仅为普通自行车，不扩展电动自行车、共享单车车辆数据、租赁或购票。
没有路线、网络失败、服务拒绝、无效 JSON 或折线时返回失败，不伪造路线或回退 Mock。
Mock 仅提供明确标注的离线起终点摘要。

## 影响与兼容

- 消费者为客户端地图 Controller 与导航页，代码仍由用户端负责人维护。
- 不修改项目 TCP、`IChargingApi`、共享协议、服务端或数据库；无数据库迁移。
- 从订单进入导航仍使用既有站点详情接口；路线规划直接访问腾讯，位置和 Key 不入库。
- 当前地图契约兼容增加 `CYCLING`，不升级 TCP V2。更新本地 fixture 与客户端说明。
- 腾讯地图适配器允许注入调用方持有的网络管理器，以便离线测试其完整响应处理；默认
  运行继续使用自有 Qt 网络管理器，不影响项目 TCP 适配器。

## 验证

覆盖 Mock 四种方式、UI 骑行选项、腾讯骑行成功及步行回归、无路线、服务错误、非法
JSON/折线和网络超时。通过内存网络替身校验请求路径、经纬度顺序、解码结果和一次完成。
真实骑行路线仍需有效 Key、WebEngine 与网络手工验收，自动测试不保证实时通行状况。
