# ADR 0017：Demo 预约保留 30 分钟

状态：IMPLEMENTED（用户明确批准的 ACCEPTED 子集）。日期：2026-09-08。

## 范围与消费者

用户端需要知道赴约截止时间，其他用户需要及时使用未赴约者占用的电桩。
影响服务端 ApplicationService、客户端 MockChargingApi 和预约展示；管理端继续
消费既有订单、桩状态。不启用保留文档中的月违约、禁约、罚款或复杂预约策略。

## 规则

- 固定保留 1800 秒，以订单 `reservedAt` 为起点；`now >= reservedAt + 1800 秒`
  且仍为 `RESERVED` 时，改为 `CANCELLED` 并在同一事务释放该订单占用的电桩。
- 开始充电必须在截止时间之前。服务端在开始前同步检查，不依赖客户端计时或定时器
  是否已经执行。过期预约 ID 按既有非 RESERVED 规则返回 `40903`，不转为直接充电。
- 服务端独立定时检查，退出登录/关闭客户端不延长预约；启动时补处理旧数据库中已到期
  的预约。请求读取订单/站点和预约/开始/取消前也检查，避免展示或使用过期占位。
- 不扣款，不累计违约，不改变已开始充电的订单、历史价格快照或结算。取消单保留
  `reservedAt`，不填写 `startedAt/endedAt/paidAt`，时长、电量、金额仍为零。
- 界面展示北京时间的截止日期/时间，不靠本机时钟伪造取消结果；刷新后展示服务端状态。
  手动取消与超时均显示“已取消”，当前数据不能可靠区分两者。

## 兼容与迁移

这是用户批准的 V1 固定预约保留策略，复用已存在的 `RESERVED -> CANCELLED` 转换，
消息成功/失败形状、字段、单位、错误码及各状态的含义不变，不增加协议版本。
`reservedAt` 已持久化且预约必填，无需数据库迁移、到期字段或新状态；已有有效预约也
按原预约时间计算，不因升级重置 30 分钟。服务端和客户端 Mock 同步实现，生产方负责
权威截止判定；旧客户端可识别 CANCELLED，但没有截止提示，旧服务端不提供自动回收。
客户端的新提示需配套本次服务端版本，不能将 UI 升级当成服务端已启用策略。

## 验证

注入时钟覆盖 29:59、30:00、超过 30 分钟、跨日、启动补处理、离线定时回收、重复
回收、过期预约启动拒绝、事务失败回滚、重新预约以及已经充电不受影响。
客户端验证截止提示、自动状态同步，以及开始前预约消失时不悄悄创建直接充电单。
固定策略与边界样例见契约 fixture，不增加可由客户端填写的到期时间。
