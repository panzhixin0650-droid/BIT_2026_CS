# ADR-0008：模拟真人客服与持久客服工单

- 状态：Accepted（用户已明确授权跨模块实现，待合并）。
- 日期：2026-09-07。
- 消费者：用户端客服页、服务端管理员工单页；涉及客户端、共享协议、服务端及数据库。
- 范围：课程 Demo 的客服角色扮演与工单反馈，不部署真人坐席系统。

## 决策

保留原有 `gpt-5.6-luna` 只读助理；通过客服页悬浮入口打开独立的模拟客服窗口，
使用 `gpt-5.6-sol` 对话及起草工单摘要。主提示为“已切换至真人客服”，开场角色为
“客服小悦，工号 008”；同一窗口持续显示“课程演示 · AI 模拟坐席”，模型遇到身份
询问须如实说明模拟身份，不编造真实雇员、排队或人工接入状态。

两个入口的会话与在途请求独立。用户点击转接时可带入普通助理最近最多四组成功问答；
只在内存中保留。沿用 HTTPS Responses、凭据保护、长度上限、脱敏、超时与取消机制。
默认助理不因客服升级而换模型；本地配置可单独指定 `supportModel`，默认 `gpt-5.6-sol`。

模型只生成对话或工单草稿，没有工具、业务 token、SQL 或订单操作权限。摘要展示为
可编辑的工单正文，用户核对标题与正文后点击提交，客户端才调用新增 TCP 消息。
未配置模型时明确提示不可用，仍允许手工填写工单；不伪造成功 AI 回答或工单回执。
只保存用户确认的标题与摘要，不上传、保存完整聊天记录，也不自动附带手机号、位置、
余额或订单。客服回复不能被解释为退款、解冻、设备维修或其他业务操作已执行。

## 契约、兼容与迁移

- 新增兼容 V1 消息 `support.ticket.create/list/detail`；创建人由当前 token 决定，
  用户只能查询自己的工单；冻结或失效会话仍由既有规则拒绝。
- 状态为 `OPEN`、`IN_PROGRESS`、`RESOLVED`。管理员在独立工单页查看、回复和更新状态，
  仅经 AdminFacade → ApplicationService → Repository 写入，不联动业务表。
- 客户端为每个待提交草稿生成 UUID，同一用户以相同 UUID 和相同内容重试返回同一工单；
  相同 UUID 携带不同正文拒绝。网络失败不自动重发，界面保留原草稿供核对与显式重试。
- 新增 `002_support_tickets.sql`，只创建工单表与索引，把 SQLite `user_version` 升到 2。
  原有五表、种子、金额、状态、计费和外键不变；需在停止服务并备份数据库后显式迁移。
- 新服务端同时接受 schema 1/2；schema 1 返回工单专用不可用提示，不阻止旧业务启动。
  新客户端连接旧服务端时，工单接口明确显示不支持，不影响普通助理与其他页面。
- 此增量取代 [ADR-0005](0005-client-rag-assistant.md) 中“不启用客服工单”的范围限制；
  普通助理的只读、有限会话和凭据边界保持不变。

详细字段、分页和失败语义见[工单契约](../../contracts/support-tickets-v1.md)。

## 验证

单测覆盖模型分流、角色提示、摘要失败/取消、用户确认、重复提交及会话隔离。
客户端 TCP 适配器、正式路由/Service、SQLite Repository 与管理员 Facade 做跨模块联测，
覆盖持久化、分页、重试去重、越权/冻结/未登录、管理员回复及 schema 1 兼容。
原有客户端、服务端、数据库与共享协议测试全部回归，不改动现有运行时数据库。

模型与接口参考：[GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)、
[Responses 流式接口](https://developers.openai.com/api/docs/guides/streaming-responses)。
官方接口文档不保证中转站的模型权限或可用性，实网检查须单独注明。
