# ADR-0001：Demo-first，复杂能力按需迁入

- 状态：Accepted
- 日期：2026-09-02

## 背景

项目说明书要求完成课程演示，但早期设计一次性引入了 24 张表、完整权限、审计、幂等、复杂计价、设备命令、客服和机器学习任务。它们会让多人在没有页面消费者的情况下承担大量联调成本。

## 决策

当前 `main` 以五表 Demo、精简 V1 接口和 Mock 桩为唯一实现主线。旧复杂文档放在 `docs/extension/`，作为未来需求池保留，但不自动产生开发任务。

课程要求中的多线程只在架构上保留一个可选 QThread 边界；当前运行允许串行。预测保留统一 Provider 和 1/6/24 小时 Mock 输出，不建设训练平台。

## 扩展准入

一个旧功能迁入主线前必须同时满足：

1. 已有明确的页面、接口消费者或新的验收要求；
2. 说明对客户端、服务端、数据库和 Web 的影响；
3. 数据库变化使用新的编号迁移，不重写已经共享的迁移；
4. 网络兼容增加沿用 V1，破坏性变化使用 V2；
5. 测试或 fixture 能证明新旧主流程均可工作。

## 结果

团队现在可以按目录独立开发；未来仍能逐步增加复杂功能。高并发和分布式属于底层实现替换，不应通过提前增加业务表来伪装完成。
