# ADR 0009：管理员账号管理与进程内 RBAC

- 状态：已接受并实现
- 日期：2026-09-07
- 消费者：同进程 Qt 管理员界面
- 影响范围：`server/`、`database/`、`contracts/`；用户客户端、TCP 协议和 Web 快照不变

## 背景

V1 Demo 只有固定的 `admin/123456`，登录后也没有持续保存管理员身份。项目现在需要在管理后台中新增管理员管理页面，并让系统管理员、站点管理员和用户管理员拥有真实的数据与操作边界。

## 决策

1. 保持管理员 UI 与服务端共用一个 `server-app` 进程。`AdminFacade` 保存当前管理员 ID，不新增管理员 TCP 消息或持久化会话表。
2. ApplicationService 在每次管理操作前重新读取管理员状态、角色和站点范围。界面隐藏菜单只用于改善操作体验，不能代替服务端校验。
3. 启用三个角色：
   - `SYS_ADMIN`：全部管理能力和管理员账号管理；
   - `STATION_ADMIN`：指标、订单及授权站点/电桩；
   - `USER_ADMIN`：全局摘要、用户和只读订单支持。
4. 站点范围使用现有整数 `stationId`。这保持 V1 站点 DTO 不变，数据库通过 `admin_station_scopes` 关联管理员和站点。
5. 管理员只停用、不删除。禁止停用自己或改变自己的角色；系统始终保留至少一名启用的系统管理员。
6. 新管理员使用初始密码并设置 `must_change_password=1`。完成首次改密前只能读取本人信息和修改密码，改密成功后退出登录。
7. 旧 SHA-256 密码允许兼容登录一次，成功后自动升级为带随机盐的 PBKDF2-SHA256；新增和改密账号直接使用 PBKDF2-SHA256。当前实现仍属于课程 Demo，正式公网系统应替换为平台提供的 Argon2id 密码组件。
8. 登录、创建、更新和改密写入专用 `admin_audit_logs`，详情不记录密码、哈希或完整表单。

## 数据兼容

保留已合入的 `002_support_tickets.sql`。`003_admin_accounts.sql` 仅从工单 schema 2 升级到 3，
兼容重建 `admins`，保留原管理员 ID、账号、密码哈希和显示名，并把原账号映射为启用的
`SYS_ADMIN`。迁移新增 `admin_station_scopes` 和 `admin_audit_logs`；用户、站点、电桩、
订单及价格快照、已有工单及回复均不变。迁移拒绝重复执行、缺失前置迁移及同版本异构库。

服务端兼容 schema 1/2/3：旧库仍支持原业务及固定管理员登录，不自动改写密码或执行迁移；
schema 2/3 支持工单。新管理员管理、改密和审计仅在 schema 3 启用；旧库返回
`ADMIN_ACCOUNTS_MIGRATION_REQUIRED`，界面隐藏账号管理并禁用改密。
已试用被撤销 PR 的“管理员 schema 2”不是工单 schema 2，须先备份并单独审计恢复，
不得仅修改 `user_version` 或再次套用 002/003。

工单管理复用管理员身份，不另存登录布尔授权；ApplicationService 每次读写重新校验
账号状态、首次改密和 `SYS_ADMIN` 角色。站点／用户管理员不能读取或回复全量工单。
退出、改密退出及登录失败清除授权和工单页面；界面隐藏不能替代服务端校验。

## 结果

管理员页面可以查询、筛选、新增和编辑管理员，维护角色、状态及站点范围，并提供本人改密。账号停用和授权变更会在下一次管理操作时生效。管理员界面若未来拆成独立进程，需要另行设计管理员 TCP 契约和持久化会话。

## 2026-09-08 密码长度兼容调整

按用户要求，初始和新密码最低长度由 8 调整为 6 个字符，上限仍为 128，允许纯数字。
服务端与 UI 同步校验；角色范围、旧密码校验、首次改密、加盐摘要和改密后退出保持原样。
这是同进程管理接口的输入范围放宽，不修改数据库结构或用户 TCP。
