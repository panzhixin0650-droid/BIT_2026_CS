# ADR-0007：用户端演示验证码登录

- 状态：Accepted（用户已授权实现，待合并）
- 日期：2026-09-07
- 授权：小范围调整用户端为手机号 + 验证码登录，验证码暂固定 `123456`，发送按钮为占位。

## 决策

保留现有手机号首次登录自动注册流程，不另设注册页或用户密码。登录页增加六位数字
验证码输入框和“发送验证码”按钮；新老用户在客户端校验手机号与 `123456` 后，再
调用既有登录 API。缺失、格式错误或错误验证码不触发 API 请求，也不创建用户。

发送按钮只校验手机号并显示固定演示码，明确提示暂不发送短信，不自动填入或登录。
直接输入固定码也可以登录，不引入倒计时、短信网关、验证码存储或有效期。
登录请求期间禁用输入与按钮，失败后恢复重试；成功后清空验证码，退出或会话失效后
重新登录仍需输入。页面保留现有主题、键盘操作和小窗口滚动布局。

## 兼容与安全边界

验证码只是客户端的课程演示交互，不能作为安全认证：直接调用旧 TCP 接口仍可按
手机号登录。真实短信登录必须单独设计服务端签发、校验、过期、限流和防滥用流程。

[V1 契约](../../contracts/overall-interface-v1.md) 的 `auth.user.login` 请求仍为
`{phone}`，响应、自动注册、被冻结用户拒绝登录及 token 规则均不变。
不改服务端、共享 DTO、数据库或管理员账号密码，也不迁移已有用户。现有
[登录请求 fixture](../../contracts/examples/auth-user-login.request.json) 保持有效。

## 验证

客户端测试覆盖空/错验证码不发请求、发送按钮不调用 API、已有用户登录、自动注册
后退出重登、成功清空验证码、重复提交、失败恢复、回车提交及最小窗口布局。
TCP 界面回归确认携带有效演示码通过页面后，实际登录信封仍仅发送手机号。
