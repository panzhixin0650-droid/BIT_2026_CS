# ADR-0003：用户端公共交通导航

- 状态：Accepted（本任务已实现，合并后进入主线）
- 日期：2026-09-05
- 授权：用户明确要求在可行时增加公共交通并同步说明。

## 消费者与范围

用户端站点导航页增加“公共交通”，便于用户在充电期间离站或返回取车。
当前导航页已有驾车和步行，本次只增加这一种方式，不引入其他扩展需求。

## 决策

本地 `IMapService.openRoute` 的 `RouteMode` 兼容增加 `TRANSIT`。
腾讯官方 [Web 路线规划文档](https://lbs.qq.com/webApi/uriV1/uriGuide/uriWebRoute)
支持 `routeplan?type=bus`；复用驾车使用的 URI 页面与 `QWebEngineView`，传入
起终点名称、经纬度和本地配置的 Key。使用腾讯默认策略，公交/地铁换乘、路线是否可用
由腾讯页面展示，不自行生成班次或票价。页面加载成功只代表网页已加载，不保证有可用路线。

Mock 保持离线，只展示公共交通的起终点摘要和 Mock 标记。未知本地模式应失败，
不能默认为步行。真实模式失败不会回退到 Mock。

## 兼容与责任

- 代码位于 `client/`，由用户端负责人维护；消费者是地图 Controller 与导航页。
- 不修改 `TcpChargingApi`、共享协议、项目 TCP 消息、订单 DTO 或服务端路由；
  通信负责人无新增实现任务。
- 从订单发起导航仍按既有 `station.detail` 获取站点信息；已有坐标后，路线查询由客户端
  直接访问腾讯 HTTPS 服务。“客户端本地适配”不等于真实地图可离线运行。
- 保留 `DRIVING/WALKING` 的含义，地图本地模式不进入网络信封，因此不需要 TCP V2。
- 数据库和 Web 大屏无变化，不需要数据库迁移；位置、路线与 Key 不入业务数据库。
- 更新 V1 §8.3 与本地 fixture；不把复杂扩展文档整体提升为当前需求。

## 验证边界

自动测试覆盖 Mock 三种模式、公共交通 URL 的端点/模式编码、配置缺失与非法坐标/模式，
以及导航页选择公共交通的操作。真实公交/地铁方案需使用本地有效 Key、WebEngine 和网络
手工验收；自动测试不访问腾讯，也不宣称验证班次、票价或实时可达性。
