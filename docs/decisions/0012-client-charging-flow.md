# ADR 0012：找桩、扫码与充电会话分离

状态：IMPLEMENTED（用户于 2026-09-08 明确要求先规划后实施）。

## 依据与调研

- 用户参考图 `/home/bit/workplace/1.jpg`：整页相机背景、扫描提示、手动编号入口。
- `/home/bit/workplace/2.jpg`：深绿色独立充电页、大圆形进度、功率/电量/时长/费用。
- [Tesla 非 Tesla 车辆操作](https://www.tesla.cn/support/charging/supercharging-other-evs)：插枪后在应用中选择对应桩号启动。
- [Electrify America 操作](https://www.electrifyamerica.com/charging-your-ev/)：找站、选桩启动、监测和停止充电是相连但独立的任务。
- [ChargePoint 应用功能](https://www.chargepoint.com/drivers/support/faqs/what-can-i-do-chargepoint-app)：地图找桩、启动充电、客服功能并存。

当前代码的 `order.start` 已支持直接启动和预约转充电，客户端却通过 ScanPage 填码中转；首页和订单详情又各自维护进度和停止。重构复用现有业务接口，统一会话展示。

## 页面与流转

| 底部入口 | 职责 |
| --- | --- |
| 首页 | 地图、搜索、站点详情、具体桩选择、预约和导航。当前订单仅保留摘要及前往充电入口。 |
| 充电 | 无选桩提示、待启动确认、预约转充电、实时进度、提前停止、结束/待支付结果。 |
| 扫一扫 | 打开占满客户端内容区的相机；手输/图片/二维码只选择桩，成功进入充电待启动状态。 |
| 客服助理 | 保持现有对话和客服工单；保留按桩报修入口。 |
| 我的 | 个人资料、钱包、我的订单（二级页面，含返回）、退出登录。 |

首页选定具体桩/预约订单 → 充电待启动 → 用户明确开始 → CHARGING → 自动或手动结束 → COMPLETED / PENDING_PAYMENT。
扫码和手输识别 → 同一待启动页，不直接创建收费订单。已有当前订单时恢复它；禁止开启第二个订单。退出相机立即释放设备，切换页面不停止充电。

用户随后要求视觉与其他主页面一致：充电页采用全局浅色背景、白色圆角卡片与自然绿色圆环；按钮区分深绿主操作、浅绿结束操作、并排辅助入口和轻量报修入口。参考图仅保留大圆环与指标布局。扫一扫保留全屏视频，以绿色取景标记、浅色底部卡片及分层按钮统一视觉。

## 模拟与服务端边界

默认每次模拟 180 秒，圆环表示本次模拟会话进度，不伪称真实车辆 SOC。实际时长、电量和金额仍以服务端为准。示例值由每次订单的开始时间独立计算。

服务端定时检查超时充电订单，复用停止/释放桩/原子结算逻辑。到达目标时自动停止，客户端退出也不影响；重启后补处理到期订单，重复检查不重复扣款。提前停止按实际时间结算，余额不足保留待支付并允许充值。

本次不新增数据库表和状态。新增会话完成策略属于共享可观察语义，在 V1 合同中补充说明和对应 fixture；序列化继续使用现有订单 DTO。

5. 在 360×640 与桌面窗口下检查布局，启动连接好的真实地图版本供验收。

## 与 main #40 / #41 的整合

- 主窗口保留首页地图的真实瓦片就绪信号，再预加载导航；工单入口使用应用内页面。
- CMake 同时保留扫码和装饰测试，补齐 main 遗漏的 `decorations.qrc`，个人页同时显示
  “我的订单”入口和手绘盆栽。充电会话决策改为 ADR 0012，避免与离线地图 ADR 0011 重号。
- Qt 6.2 隐藏地图的内部渲染控件会延迟处理尺寸事件，导致 SDK 首次看到 0×0 容器。
  SDK 初始化前激活布局并向隐藏渲染控件传递当前尺寸，不显示额外窗口或转移登录焦点。
  依据 [Qt 6.2.4 WebEngine 视图实现](https://github.com/qt/qtwebengine/blob/v6.2.4/src/webenginewidgets/api/qwebengineview.cpp)
  中加载期间插入渲染控件的行为，以及现有预加载测试在本机的失败与修复验证。
- WebEngine 导航测试使用桌面/Xvfb；本机 Qt 6.2 的 offscreen 软件场景图在地图重载时
  发生崩溃，不能用该平台替代真实渲染检查。非 WebEngine 测试仍支持 offscreen。
- 导航截图回归在“扫一扫”返回后再检查底栏，适配全屏相机交互；离线底图检查等待
  异步就绪，替代固定 400 毫秒延迟。无窗口管理器的 Xvfb 环境先激活登录窗口，再验证
  地图预加载期间输入焦点不变。地图超时、实例复用和失败重载的原有断言保留。

整合验证（2026-09-08）：WebEngine + 扫码构建通过；客户端 18 个测试集通过

的基础构建及主窗口、装饰、站点地图 3 集通过。实际 RGB 摄像头连续取帧、刷新设备、
