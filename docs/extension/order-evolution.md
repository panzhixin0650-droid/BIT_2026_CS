# 订单扩展候选与现有接入位置

状态：`IDEA`，未激活。当前实现仍以 [Demo 契约](../../contracts/overall-interface-v1.md)及五表迁移为准。

本说明对照两份[复杂版保留文档](README.md)与用户提供的外部工作簿 `01需求矩阵-第5组-潘治鑫(3)_副本.xls`（“需求进度管理表”）整理。该工作簿不是仓库内的当前契约，进度栏也不代表代码完成状态。下表按工作簿 NO. 标识需求。

| 候选需求 | 当前 Demo 行为 | 未来接入位置及所需变更 |
| --- | --- | --- |
| NO.4、9：30 分钟预约到期、月违约与禁约 | 预约只可开始或主动取消，没有到期时间 | 在 ApplicationService 的预约规则处扩展；批准后增加到期字段、`EXPIRED` 状态及定时处理，迁移状态约束，更新客户端契约/fixture |
| NO.7：快慢充与峰谷计价 | 开始时冻结站点单价，单次整数计费 | 当前计费集中在 `order_billing.h`；批准后增加计价策略及必要快照/计费段，保留历史订单原单价和金额 |
| NO.10：扫码、直接与预约充电 | `order.start` 使用 `pileCode`；传入预约 ID 时复用原单，省略时直接开单 | 目前可复用客户端已有输入方式；未来扫码只负责解析并提供桩编号，服务端继续校验归属、状态和价格，不信任二维码携带的计费字段 |
| NO.4、11、23：充电故障与报修 | 五种订单状态；当前没有故障终止/报修消息 | 在服务层新增经批准的状态转换，使用 `IPileGateway` 处理设备边界；增加故障表和相应状态迁移，再更新 UI 和消息 |
| NO.20 与保留文档：完整账单历史、流水/退款 | 持久化订单关键时间、电量、价格、金额及支付结果 | 在现有订单事务内追加后续流水/状态历史 Repository 操作；退款依赖钱包流水，需单独批准接口和迁移 |
| 真实设备 | `MockPile` 实现 `IPileGateway` | 通过相同业务边界引入适配器；远程失败、确认和补偿协议单独设计，不能假设设备动作可被数据库回滚 |

当前接入边界有实际消费者：`IPileGateway` 用于 Demo 充电读数和测试设备替身；Repository 事务用于订单、桩和余额的原子修改；统一计费函数用于进度和最终账单。没有为了未来需求新增空实现 TCP 消息或返回成功的占位业务方法。

激活扩展时遵循仓库的 `IDEA → ACCEPTED → IMPLEMENTED` 流程：明确消费者，记录决策，更新当前契约与 fixture，再添加编号迁移和实现。保持 integer ID、整数分/Wh、UTC 时间和已有 `stop` 自动结算语义；破坏性网络变化使用 V2。不得把保留文档中的 24 表 DDL 直接叠加到现有数据库。
